How Ava answers a customer, and why it's built this way

Ava is an AI support agent for a demo online shop. It looks up real orders, follows the shop's written policies, and refuses to show anyone else's data. This page explains how, from first principles, with things you can click.

Part 1

Six ideas explain the whole system

A language model is like a smart new employee on day one: fluent and polite, but it doesn't know your orders, your rules, or who may see what. Each idea below gives it one of those missing things.

1 · LLM

The language model

The smart new employee

Reads the message, decides what to do, writes the reply. Here it's Claude Haiku 4.5. It can only ask for data, never touch it.

2 · Tools

Function calling

The phone to the warehouse

Small programs the model may request: lookup_order and check_account_status. Our code runs them and hands back the result.

3 · RAG

Retrieval

The policy handbook

Before answering a policy question, the right handbook page is found and pasted into the model's instructions. Six pages in total.

4 · Embeddings

Search by meaning

A map of meanings

Text becomes 1,536 numbers, like coordinates. "Money back" lands near "refund policy". The closest page under the cutoff wins.

5 · Gate

The permission gate

The supervisor

Plain code checks every tool request before it runs: is the ID valid, and does it belong to this customer? No wording can talk it round.

6 · MCP

A standard tool plug

USB for AI tools

The tools live in a separate MCP server that checks ownership a second time. Two locks, and any MCP app could reuse them.
